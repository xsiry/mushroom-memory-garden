# 蘑菇家族 记忆排序

可直接运行的手机网页游戏。玩法和七张蘑菇形象来自本目录两份 Word 文档。详细规则、改进思路、视觉规范和技术选择见 [DESIGN.md](DESIGN.md)。

## 开始游玩

双击 `启动游戏.command`，或在项目目录执行：

```sh
npm start
```

电脑打开 `http://localhost:4173/`。终端会显示本机局域网地址，并自动生成 `outputs/扫码游玩.svg` 和 `outputs/本机访问地址.txt`。手机与电脑连接同一个 Wi-Fi 后扫描二维码。地址随网络变化，重启服务会重新生成；不要将 localhost 用作手机地址。

首页“扫码入口”会生成当前游戏入口的二维码，可保存为 900×900 PNG 图片。

公网版本已部署到 [游戏入口](http://47.102.205.35:18088/)，可直接在手机打开，或使用 [PNG 扫码图片](http://47.102.205.35:18088/entry-qr.png)。项目部署于服务器 `/home/apps/mushroom-memory-garden`，运维和回退说明见 [deployment/README.md](deployment/README.md)。公网入口独立运行；本机睡眠、关机只影响本机的局域网预览。

## 游玩和领奖

1. 选择 3–7 张卡片和 3、5、8、10、15 秒记忆时间。
2. 从左到右、从上到下记住蘑菇顺序。
3. 按原顺序点选打乱的卡片；再点已选卡片即可撤回，选齐后确认。
4. 通关后打开领取凭证，到活动现场礼品领取处出示原手机实时页面。
5. 工作人员核对日期和编号、实际发放礼品，再点击“交给工作人员核验”，勾选已发放并确认核销。

每天在同一浏览器只生成一张凭证，核销后再通关不会重新发券。失败可以查看对照并原题重试。记忆中途离开页面或刷新会暂停，返回主动继续；排序中的选择也会保留。

纯前端保存依赖游客当前浏览器，不能跨设备统一防重或抵御本地数据修改，清理浏览器数据会丢失记录。现场小礼品建议由工作人员结合实际游客和领取登记核验。禁止存储时游戏仍可玩，但提示无法保存，需保持页面打开并现场说明。活动高价值奖品需要另行接入服务端。

## 项目结构

- `src/game.js`：随机抽样、排序规则、凭证与存档边界校验。
- `src/storage.js`：浏览器本地读写与存储失败降级。
- `src/views.js`、`src/dialogs.js`、`src/app.js`：界面、弹层、游戏状态与交互。
- `src/qr.js`：无外部依赖 QR Model 2 Version 5-L 编码，支持最长 106 字节网址。
- `assets/mushrooms/image*.png`：从 Word 提取的原始图片；同目录 WebP 是透明裁剪、压缩的网页资源。
- `scripts/serve.mjs`：本地静态预览和局域网扫码入口，仅提供明确白名单资源。
- `tests/`：规则和异常边界回归。
- `outputs/qa/`：浏览器多轮回归截图、结果及性能证据。

## 构建与验证

运行环境为 Node.js 22 或更高版本，不需要安装 npm 依赖。

```sh
npm test
npm run build
node scripts/serve.mjs --dist
```

`dist` 包含完整静态游戏、资源和构建信息，无需服务端业务程序。可以托管在域名根目录或子目录，页面与图片均使用相对路径。

自动浏览器回归使用本机已提供的 Playwright 和 Chrome：

```sh
GAME_URL=http://localhost:4173/ QA_OUTPUT=outputs/qa/current-smoke node scripts/deployment-smoke.mjs
```

若测试运行环境不在 Codex 自带依赖目录，通过 `CODEX_NODE_MODULES` 指向已有 `node_modules`；测试不会安装或下载依赖。macOS 可用 `swift scripts/verify-qr.swift outputs/qa/qr-decode.png` 独立验证二维码识别。

## 隐私与活动配置

不要求游客登录，不收集姓名、手机号、定位、相册或第三方统计。可开关游戏提示音。所有资源本地提供，不请求外部字体、CDN、追踪服务。游戏形象不用于野生菌识别或食用建议。

活动正式使用前，应在实际手机、微信扫码浏览器、现场 Wi-Fi 和礼品发放流程中完成验收。本次自动桌面浏览器的手机视口证据不能替代真实手机与现场验收。
